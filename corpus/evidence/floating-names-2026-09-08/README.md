# Floating-name conformance

The copied final CLI matches **11,088 native observations**, with no acceptance
mismatches. The matrix covers seven names, 22 declaration/scope cases, all eight
C modes, GNU x86-64/AArch64, and Clang on all seven physical targets. Complete C
source, compiler argv, exit status, stdout, and diagnostics are retained in the
archive. Compiler crashes are rejected by the probe runner.

The cases distinguish real keywords, GNU's shadowable predefined `__float128`
typedef, and ordinary Clang identifiers. They include replacement and conflicting
typedefs, prior uses, local and parameter shadowing, prototype scope restoration,
tags, fields, enumerators, labels, functions, and explicit source macros. Separate
native probes and regression tests cover block `extern` declarations. The first
candidate's 16 remaining GNU x86 file-name mismatches are preserved in the external
cache; final evidence uses the corrected frozen binary.

All eight untouched zlib, SQLite, zstd, and libgit2 header outputs remain
byte-identical under the modern GNU/Clang defaults. Real glibc headers accept both
defaults. Forcing GNU version 4 selects a replacement `_FloatN` typedef branch that
both native GCC and Toucan reject; Clang accepts the same ordinary aliases.

Generated FloatN fixed, stacked-argument, record, callback, and C-side variadic
consumers pass with C O0/O2 and Rust O0/O3 under current Rust and actual Rust 1.64.
Generated glibc `strtof32`, `strtof64`, `strtof32x`, and `cosf32` calls also pass
with both Rust versions at O0/O3. Unsupported `_Float64x` and `_Float128` Rust
scalar calls retain their explicit diagnostics.

The focused semantic/native suite passes 40 tests, the facade suite passes three,
and binding tests pass two. The final checked replay passes **8,448** seed/profile/
mode pairs: 5,569 accepted and 2,879 rejected, with ordinary/retained equivalence
and graph invariants. Workspace and fuzz Clippy pass with warnings denied.

The parser's generated bytes and grammar are unchanged; this layer adjusts the
lexical environment and removes compatibility recovery from semantic analysis.
The parent integration runs full workspace/platform/sanitizer gates. This record
contains no new timing or sanitizer claim. Native runtime runs were on x86-64
Linux; cross-target syntax probes do not establish runtime behavior elsewhere.

`summary.json` records source, archive, and frozen binary hashes. The archive
contains native observations, candidate comparisons, header and runtime results,
compiler identities, source hashes, scripts, primary keyword tables, and logs.
Scripts retain the original devbox compiler and cache paths; each source and
complete argv is available for replay with equivalent toolchains.
