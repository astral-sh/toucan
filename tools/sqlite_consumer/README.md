# SQLite consumer validation

This fixture builds rusqlite 0.40.2 and libsqlite3-sys 0.38.2 with bindings
regenerated by Toucan. Their source is pinned to
[`e88f112bef7899234a497baed5cc3c3d553deeb8`](https://github.com/rusqlite/rusqlite/tree/e88f112bef7899234a497baed5cc3c3d553deeb8).
`Cargo.lock` pins the complete dependency graph, without bindgen or libclang.

Run from the repository root:

```sh
cargo build --locked --release -p toucan_cli --no-default-features
python3 scripts/verify_sqlite_consumer.py \
  --toucan target/release/toucan \
  --target x86_64-unknown-linux-gnu --sysroot / \
  --output corpus/results/sqlite-consumer
```

On macOS, use the native target and `--sysroot "$(xcrun --show-sdk-path)"`.
The requested target must match the Rust compiler's host. The script rejects
other targets before resolving dependencies or building the consumer.
The script copies the pinned sys crate to its cache and replaces only
`sqlite3/bindgen_bundled_version.rs`, the input copied by upstream's build script.
All Rust wrapper code, C source, C compilation flags, and linking are unchanged.
Generated Rust is used directly without postprocessing.

The profile follows the consumer's
[`build.rs`](https://github.com/rusqlite/rusqlite/blob/e88f112bef7899234a497baed5cc3c3d553deeb8/libsqlite3-sys/build.rs):

- C string constants use `CStr`.
- `SQLITE_SERIALIZE_NOCOPY`, `SQLITE_DESERIALIZE_*`, `SQLITE_PREPARE_*`, and
  `SQLITE_TRACE_*` use unsigned Rust integer types. The report retains their
  original C types, and a C probe checks the original values before conversion.
- Two automatic-extension functions are blocked and replaced by the caller's
  declarations in `auto_extensions.rs`, using the signatures supplied by upstream.
  SQLite's header accepts generic `void (*)(void)` pointers; SQLite invokes those
  entry points with a database, error-message pointer, and API table. The report
  distinguishes these caller-supplied declarations from analyzed C declarations.

Before these policies, compiling the same wrapper with Toucan's default output
produced 13 type errors: two callback signatures and eleven signed flag uses.
Other upstream exclusions, including UTF-16 functions, are unnecessary for this
consumer build and remain available. C macro types are preserved by default;
upstream's global signed-inference policy is not reproduced here.

The executable uses the `bundled`, `serialize`, `trace`, and `functions` features.
It inserts 32 rows with prepared parameters, calls Rust scalar and trace callbacks
from C, registers and cancels an automatic extension, serializes and restores a
database, and checks the public version `CStr` against the linked C library.
A separate C probe checks every emitted integer and string constant plus the
existing SQLite layout inventory. Automatic-extension ABI compatibility is tested
by actual callback execution; caller-supplied Rust is not inferred from the C AST.

The evidence includes commands, output, dependency checksums, tool versions,
generated source and report hashes, and before/after hashes for upstream Rust,
C, and build-script sources. CI runs the fixture on native Linux and macOS x86_64
and AArch64. This covers the current compiler and those features; loadable
extensions, SQLCipher, session/preupdate hooks, and the consumer's MSRV remain
separate acceptance gates.
